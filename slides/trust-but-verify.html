Trust, but Verify

Your deep agent demos beautifully. It plans, delegates, and writes something that reads well. Now answer the only question that matters before it ships: how do you know it’s right — and how will you know next week, after someone edits a prompt?

01

The most persuasive memo was the least defensible

Three configurations. Same subagents, same tools, same data, same question.

Configuration Grounding Citations Fabricated Ships?
naive no skills, no grounding rules, no verification 90.9% 0 0 no
baseline skills + grounding rules, nothing checks them 99.2% 32 0 yes
verified + verifier subagent + runtime rubric loop 98.6% 42 0 yes

Sit with the naive memo. It made roughly twenty claims about Apple’s China antitrust exposure, EU DMA fines, and tariff guidance, and attributed none of them. It quietly rounded six real tool outputs into tidier numbers. And it is comfortably the best-written of the three — the only one that closes with a prioritised action plan.

Reading it carefully would never have told you. That is the whole problem: fluency and defensibility are uncorrelated, and only one of them is visible to a human reviewer.

02

Three loops

Numbered by dependency, not by sequence — Loop 0 is the one the other two rest on.

grounded Traces to a recorded tool result or a fetched source.
unsupported Nothing recorded supports it. It may still be true — we simply cannot tell.
fabricated Cites a source never fetched, or quotes text that is not in it. Never negotiable.

Splitting unsupported from fabricated is not pedantry. “I cannot find this” and “this contradicts what we recorded” call for different human responses, and collapsing them into a single fail throws away the signal that tells you which.

03

A subagent is a context window with a job

Three deep agents, one deliberately shallow, and a single append-only ledger.

You cannot evaluate what you did not record. Recording is middleware, not tool code — because a tool that must remember to participate in its own audit trail eventually won’t.

04

The bug this repo caught in itself

Nothing errored. The agent ran beautifully. The evidence was gone.

Before 79.28% recorder on supervisor only
After 99.24% recorder on every subagent
Diff 1 line plus a regression test

The verifier reported $18,420.55 — the actual cash balance, straight out of get_account_balances — as unsupported. Declarative subagents are compiled with their own middleware stack, so every tool call made inside a subagent never reached the ledger. The evidence was destroyed at the boundary between two context windows, which is the exact thesis of this workshop. The system caught it on itself.

The lesson outlives the bug: in a multi-agent system, cross-cutting concerns must be installed per agent. Logging, redaction, rate limiting and audit trails all have this shape, and all of them fail silently the same way.

05

The judge is an application too

Same model throughout. Twenty labelled fixtures. Three prompt versions.

Judge prompt Agreement Blessed a bad memo Flagged a good one
v1 naive a reasonable first draft 85% 2 1
v2 strict written after reading v1’s mistakes 85% 0 3
v3 calibrated after reading v2’s over-correction 95% 0 1

Look at v2. By the headline number it was a complete waste of time — 85% before, 85% after. It had in fact eliminated the entire dangerous error class and introduced a milder one. A single agreement number would have told you to throw away the change that mattered most.

This is also where the deterministic checker stops. It agrees with human labels on 18 of 20 fixtures for free. One miss states 34.71% of the portfolio using a real number that measures share of equity — every digit checks out and the sentence is false. No number-matcher can see that. The other miss lets a fabricated 12% through because a genuine 11.88% rounds to it. Tighten the tolerance and honest reformatting starts failing. No setting avoids both.

06

What verification costs

Stated plainly, because the trade is the audience’s to make.

Tokens · verified run 1.78M supervisor + four subagents
Wall clock 17.6m naive run: a fraction of it
Deterministic check $0 18 of 20 defects, no model

Whether that trade is worth making depends entirely on what happens at your company when a memo is wrong — which is a decision for the room, not for me. You can only have the argument if both numbers are on the table.
